# Relay

เว็บแอปบนเครื่องสำหรับสั่งงาน Codex, Claude Code และ Gemini ผ่าน Git repo เดียวกัน เปิดที่ [http://127.0.0.1:4782](http://127.0.0.1:4782)

## เปิดใช้งานบน Windows

ใช้ Node.js 22.13 ขึ้นไปและ Git จากนั้นรันใน PowerShell

```powershell
Set-Location D:\AI\relay
npm.cmd ci
npm.cmd run build
npm.cmd start
```

เปิด Relay ด้วย `start-relay.bat` เพื่อให้รีสตาร์ทในหน้าต่างคอนโซลเดิมได้ ไฟล์นี้จะติดตั้ง dependencies และ build หน้าเว็บให้หากยังไม่มี ถ้าเตรียมทั้งสองอย่างไว้แล้ว จะเปิดด้วย `npm.cmd start` โดยตรงก็ได้

## รีสตาร์ท Relay หลัง merge

หลัง merge งานที่แก้ `relay/server` หรือ `relay/mcp` ให้กด **รีสตาร์ท Relay ตอนนี้** ในกล่อง **อัปเดต Relay** ของการ์ดขั้นต่อไป หากต้องการให้ Relay สั่งรีสตาร์ทเอง ให้เปิด **รีสตาร์ท Relay อัตโนมัติหลัง merge งานที่แก้ server** ในหน้า **ตั้งค่า** ตัวเลือกนี้ปิดไว้เป็นค่าเริ่มต้น

ทั้งการกดปุ่มและการรีสตาร์ทอัตโนมัติจะรอจนไม่มีงานในคิว งานที่กำลังรัน งานที่กำลังหยุด หรืองานที่รออนุมัติ หน้าเว็บจะแสดงสถานะระหว่างรอและให้ยกเลิกคำขอได้ เมื่อ Relay กลับมาทำงาน แท็บเดิมจะเชื่อมต่อใหม่เอง

เมื่อเปิดด้วย `start-relay.bat` ให้เปิดหน้าต่างคอนโซลเดิมค้างไว้ สคริปต์จะรอให้เซิร์ฟเวอร์ตัวเดิมหยุดก่อนรัน `npm.cmd start` อีกครั้งในหน้าต่างเดิม จึงเห็น log ของทั้งสองรอบ สคริปต์เปิดเบราว์เซอร์เฉพาะตอนเริ่มครั้งแรก เว้นแต่ตั้ง `RELAY_NO_BROWSER=1`

ถ้ารีสตาร์ทไม่สำเร็จ ให้ดูข้อความผิดพลาดบนหน้าเว็บหรือในหน้าต่าง `start-relay.bat` หากเซิร์ฟเวอร์หยุดหรือเริ่มใหม่ไม่สำเร็จ สคริปต์จะแสดง `Server stopped` พร้อม exit code เมื่อไม่เป็น 0 และรอให้กดปุ่มเพื่อให้มีเวลาอ่าน log เมื่อแก้สาเหตุแล้ว หากเซิร์ฟเวอร์หยุดอยู่ ให้เปิด `start-relay.bat` อีกครั้ง

## สร้างงาน

1. ที่หน้า **ตั้งค่า** เลือก AI ตัวหลักและตัวสำรองสำหรับแต่ละขั้น ตั้งโควตาที่กันไว้สำหรับรีวิว และกำหนดจำนวนรอบส่งกลับไปแก้
2. กด **สร้างงาน** ใส่พาธแบบเต็มของ Git repo ที่มี commit และระบุเกณฑ์รับงาน แอปเริ่มจาก HEAD และส่งโจทย์พร้อมไฟล์โค้ดที่ commit แล้วบางส่วนไปยังผู้ให้บริการที่ถูกเลือก ไฟล์ที่ยังแก้ค้างใน checkout ปัจจุบันจะไม่ถูกนำเข้า
3. ดูประวัติว่าใครรับงานและทำไมถึงข้ามตัวหลัก แอปลองตัวสำรองเมื่อ AI ไม่พร้อม โควตาถึงระดับที่กันไว้ หรือคำขอล้มเหลว ถ้าไม่มีตัวพร้อม งานจะแจ้งว่าติดขัดและให้สร้างงานใหม่จากโจทย์เดิมได้
4. เปิด **Git diff** และดูผลรีวิวในหน้างาน ผลรวมยังอยู่บน branch `relay/<id>` ใน worktree แยก คุณเลือก merge เองผ่าน Git ได้ หากเกิด conflict ให้ตรวจจาก branch ของ Backend และ Frontend ที่ระบุในประวัติงาน

ถ้าเลือกให้ทดสอบ แอปจะรันสคริปต์ `test` และ `build` ที่มีใน `package.json` ที่ root หากมี dependencies แอปใช้ `npm ci --ignore-scripts` เพื่อเตรียมจาก lockfile สคริปต์ของ repo รันบนเครื่อง จึงควรใช้ตัวเลือกนี้กับ repo ที่ไว้ใจ

เวอร์ชันนี้รองรับการเพิ่มและแก้ไฟล์ข้อความ งานที่ต้องลบไฟล์หรือสร้างไฟล์ไบนารีอาจต้องแก้ต่อจาก branch ผลลัพธ์ worktree ผลลัพธ์อยู่ใต้ `.relay/worktrees`

## ข้อมูลของแอป

คิวงาน ประวัติ โปรเจกต์ การตั้งค่า และการเรียก AI แต่ละครั้งเก็บใน SQLite ที่ `.relay/relay.db` เมื่อเปิดเวอร์ชันนี้ครั้งแรก แอปย้ายข้อมูลจาก `.relay/state.json` เข้า SQLite ให้เอง แล้วเก็บไฟล์เดิมไว้เป็น `state.json.migrated`

ถ้าแอปปิดระหว่างที่งานกำลังรัน เมื่อเปิดใหม่งานจะกลับเข้าคิวและทำต่อจากขั้นที่ค้าง แผนและขั้นที่เสร็จแล้วไม่ถูกทำซ้ำ ถ้าแอปปิดระหว่างงานเดิมเกิน 3 ครั้ง งานจะหยุดเป็นถูกขัดจังหวะ

แท็บ **การใช้ AI** ในหน้างานแสดงการเรียก AI ทุกครั้ง ทั้งเวลา token และค่าใช้จ่าย ค่าใช้จ่ายของ Claude Code ที่ใช้บัญชี claude.ai เป็นมูลค่าเทียบราคา API ไม่ใช่เงินที่จ่ายจริง Codex และ Gemini CLI ยังไม่รายงาน token

## Task Card

Task Card คือ JSON ที่บอก Relay ว่าต้องทำอะไร ใช้ส่งงานจาก Chat เข้า Relay ได้ทั้งผ่าน MCP (ด้านล่าง) และวางเองในหน้า **สร้างงาน → วาง Task Card** ดู schema เต็มได้ที่ `GET /api/cards/schema`

```json
{
  "version": 1,
  "title": "เพิ่มปุ่มสลับธีม",
  "project": "Acceptance Report",
  "type": "feature",
  "goal": "ผู้ใช้สลับธีมสว่างหรือมืดได้ และค่าที่เลือกคงอยู่หลังรีเฟรช",
  "context": "ใช้ GET และ PUT /api/preferences/theme โดยส่ง JSON ที่มีฟิลด์ theme เป็น light หรือ dark",
  "scope": { "include": ["webapp/web_app.py", "webapp/test_theme.py", "webapp/static/**", "webapp/templates/**"] },
  "constraints": ["คงพฤติกรรมของ API เดิม"],
  "acceptance": [
    { "text": "เทสการอ่าน บันทึก และตรวจค่าธีมผ่าน", "check": "command", "command": "py -3 -m unittest discover -s webapp -p test_theme.py" },
    { "text": "ปุ่มอยู่มุมขวาบนและแสดงธีมที่บันทึกไว้หลังรีเฟรช", "check": "manual" }
  ],
  "subtasks": [
    {
      "role": "backend",
      "title": "เพิ่ม API สำหรับธีม",
      "goal": "อ่านและบันทึกธีมของผู้ใช้ผ่าน /api/preferences/theme",
      "files": ["webapp/web_app.py"],
      "acceptance": "PUT รับค่า light หรือ dark เท่านั้น และ GET อ่านค่าที่บันทึกไว้ได้",
      "dependsOn": [],
      "prefer": "codex"
    },
    {
      "role": "frontend",
      "title": "เพิ่มปุ่มสลับธีม",
      "goal": "อ่านค่าธีมเมื่อเปิดหน้าและบันทึกค่าที่ผู้ใช้เลือก",
      "files": ["webapp/templates/index.html", "webapp/static/theme.js", "webapp/static/style.css"],
      "acceptance": "สลับธีมจากปุ่มมุมขวาบนได้และธีมยังอยู่หลังรีเฟรช",
      "dependsOn": [],
      "prefer": "claudecode"
    },
    {
      "role": "backend",
      "title": "ทดสอบ API สำหรับธีม",
      "goal": "เพิ่มเทสการอ่าน การบันทึก และการปฏิเสธค่าธีมที่ผิด",
      "files": ["webapp/test_theme.py"],
      "acceptance": "เทสตรวจได้ว่าค่าที่บันทึกอ่านกลับได้ และ PUT ปฏิเสธค่านอกเหนือจาก light หรือ dark",
      "dependsOn": [1]
    }
  ],
  "approvals": ["after_plan"],
  "routing": { "prefer": { "backend": "claudecode" }, "budget_usd": 2 }
}
```

- `project` ใช้ชื่อโปรเจกต์ที่บันทึกไว้ในหน้า **โปรเจกต์** หรือพาธเต็มของ repo
- Relay รันเกณฑ์ `acceptance` แบบ `command` ร่วมกับคำสั่งทดสอบของโปรเจกต์ และใช้ผลล่าสุดของคำสั่งที่ตรงกันหลังตัดช่องว่างหัวท้ายและยุบช่องว่างติดกัน หากยังไม่มีผลของคำสั่งนั้นจะแสดงว่ารอตรวจ แบบ `review` ใช้ผลรีวิวล่าสุดและเป็นค่าเริ่มต้นเมื่อไม่ระบุ `check` ส่วนแบบ `manual` ให้คุณติ๊กหรือยกเลิกติ๊กในหน้างาน Relay บันทึกสถานะไว้ใน SQLite
- `scope` Relay บังคับจริง: ถ้า AI แก้ไฟล์ที่อยู่ใน `exclude` หรือนอก `include` ผลนั้นถูกปฏิเสธและย้อนกลับ แล้วให้ AI ตัวอื่นหรือรอบใหม่ทำแทน รูปแบบ: พาธไม่มี `*` หมายถึงไฟล์นั้นหรือทุกอย่างในโฟลเดอร์นั้น `*` อยู่ในโฟลเดอร์เดียว `**` ข้ามโฟลเดอร์
- `type` เลือก workflow: `feature` และ `other` แบ่งเป็น Backend + Frontend ส่วน `bugfix` (หาสาเหตุ แก้ และพิสูจน์), `refactor` และ `docs` ใช้ AI ลงมือทำตัวเดียว (ใช้เส้นทางของ Backend)
- `approvals: ["after_plan"]` ให้งานหยุดหลังวางแผนเพื่อให้คุณอนุมัติ ขอแก้แผนพร้อมหมายเหตุ หรือไม่อนุมัติ
- `routing.budget_usd` งบของงานนี้ เมื่อถึงงบ งานหยุดรอคุณอนุมัติเพิ่มงบ (ครั้งละเท่างบเดิม) หรือหยุดงาน งบตรวจก่อนเรียก AI แต่ละครั้ง งานที่ Backend กับ Frontend ทำพร้อมกันจึงอาจเกินงบได้เท่ากับการเรียก AI ที่กำลังทำอยู่

### API เกณฑ์รับงาน

`GET /api/jobs/:id/summary` ส่ง `acceptance` ที่ประเมินแล้วพร้อม `manualChecks` ส่วน `GET /api/state` ส่ง `manualChecks` ในแต่ละงาน งานที่ไม่มีรายการเกณฑ์ใน Task Card ใช้ข้อความจาก `plan.acceptance`

ส่ง `PATCH /api/jobs/:id/acceptance` พร้อม JSON เช่น `{ "index": 1, "checked": true }` เพื่อบันทึกเกณฑ์แบบ `manual` ลำดับ `index` เริ่มที่ 0 และนับจากรายการเกณฑ์ทั้งหมดใน Task Card ใช้ `checked: false` เพื่อยกเลิกติ๊ก เมื่อบันทึกสำเร็จ API ตอบ `200` พร้อม `{ ok, id, manualChecks, acceptance }` หากไม่พบงานจะตอบ `404` หากลำดับไม่ถูกต้อง เกณฑ์เป็นชนิดอื่น หรือ `checked` ไม่ใช่บูลีน จะตอบ `400`

### กำหนดงานย่อยเอง

ใส่รายการ `subtasks` ที่ระดับบนสุดของ Task Card ตามตัวอย่าง แล้วเปลี่ยนชื่อโปรเจกต์และพาธไฟล์ให้ตรงกับ repo ของคุณ

- แต่ละชิ้นต้องมี `role` เป็น `backend` หรือ `frontend` พร้อม `title`, `goal`, `files` และ `acceptance` ข้อความชื่อ เป้าหมาย และเกณฑ์รับงานย่อยต้องมีเนื้อหา ส่วน `files` เป็นรายการพาธใน repo ที่งานย่อยต้องอ่านหรือแก้ ใช้ `[]` ได้เมื่อยังไม่มีไฟล์ที่ต้องระบุ
- `dependsOn` เป็นรายการเลขงานย่อยในฝั่งเดียวกัน เริ่มนับจาก 1 ตามลำดับที่ปรากฏใน JSON ในตัวอย่าง งานทดสอบเป็น Backend #2 และรอ Backend #1 แม้มี Frontend คั่นอยู่ งานที่เริ่มได้ทันทีใช้ `[]` หรือละฟิลด์นี้
- `prefer` เป็นตัวเลือก ระบุ `claudecode`, `codex` หรือ `gemini` เพื่อให้ Relay ลอง AI ตัวนั้นก่อนสำหรับชิ้นนั้น มีผลเหนือ `routing.prefer` ของฝั่งทั้งในโหมดอัตโนมัติและกำหนดเอง หาก AI ที่เลือกไม่พร้อมหรือทำไม่สำเร็จ Relay จะลองตัวสำรองตามการตั้งค่า
- Relay ตรวจการ์ดก่อนเข้าคิว ทั้ง API และ MCP แจ้งข้อผิดพลาดเมื่อเลขอ้างอิงอยู่นอกช่วงของฝั่งเดียวกัน ชี้ไปที่งานตัวเอง หรือทำให้เกิดวงจร การ์ดใส่ได้สูงสุด 20 งานย่อยรวม และแต่ละฝั่งยังต้องอยู่ในเพดาน `team.maxSubtasks` ที่ตั้งไว้ (ค่าเริ่มต้น 4 ต่อฝั่ง)

เมื่อมีรายการงานย่อย Relay ใช้รายการจากการ์ดแทนที่รายการที่คนวางแผนแบ่งเอง คนวางแผนยังจัดทำข้อตกลงระหว่างฝั่ง เกณฑ์รับงาน และรายการไฟล์ตามปกติ หน้าตรวจแผนระบุที่มาของงานย่อย และหน้า **ภาพรวม → ติดตามงานสด** แสดงสถานะขณะทำงาน

งานย่อยจากการ์ดยังรันเมื่อ `team.mode` เป็น `off` หรือแผนจัดเป็น `simple` โดยใช้ค่า `team.parallel` และ `team.check` ตามที่ตั้งไว้ การ์ดที่ละ `subtasks` หรือใส่ `[]` ใช้การวางแผนและแบ่งงานตามการตั้งค่าปกติ

## การแก้โค้ด การอนุมัติ และงบ

- **AI แก้ไฟล์เอง:** เปิดไว้เป็นค่าเริ่มต้น Claude Code (เครื่องมือ Read, Glob, Grep, Edit, Write ไม่มี shell) และ Codex (sandbox `workspace-write`) แก้ไฟล์ใน worktree ของงานโดยตรง Relay ดูว่าไฟล์ไหนเปลี่ยน ตรวจ scope และไฟล์ต้องห้าม (เช่น `.env`, `.git`) แล้ว commit เฉพาะไฟล์ที่ AI แก้ ถ้าผลถูกปฏิเสธ Relay ย้อนไฟล์ที่ AI แก้ก่อนให้ตัวถัดไปทำ Gemini ยังส่งผลเป็น JSON ปิดได้ในหน้าตั้งค่า
- **อนุมัติแผน:** ติ๊ก "หยุดให้ฉันตรวจและอนุมัติแผน" ในหน้าสร้างงาน ใส่ `approvals` ใน Task Card หรือเปิดให้ทุกงานในหน้าตั้งค่า งานที่รออนุมัติขึ้นสถานะ "รออนุมัติ" ชื่อแท็บเป็น `(❗ n) Relay` และตอบได้ในหน้างานหรือผ่าน MCP (`relay_approve`) เวลาที่รอคุณไม่นับรวมในเวลาสูงสุดต่องาน
- **dependencies ในงาน:** worktree ของงานลิงก์ `node_modules` จากโฟลเดอร์โปรเจกต์ของคุณ (ที่ราก และในโฟลเดอร์ย่อยที่มี `package.json` เช่น `relay/`) ลิงก์เฉพาะโฟลเดอร์ที่ git ignore ไว้ จึงไม่นับเป็นการเปลี่ยนแปลง คำสั่งทดสอบของโปรเจกต์และ check แบบ `command` ใน Task Card จึงใช้ dependencies ที่ติดตั้งไว้แล้วได้เลย ถ้าลิงก์แล้ว Relay จะไม่รัน `npm ci` เพราะจะไปล้าง `node_modules` จริงของคุณ ด้วยเหตุผลเดียวกัน อย่าใส่คำสั่งที่ติดตั้งหรือลบแพ็กเกจ (`npm ci`, `npm install`) เป็นคำสั่งทดสอบ ถ้าโปรเจกต์ยังไม่เคยติดตั้ง Relay จะติดตั้งในงานแบบเดิม
- **งบ:** ตั้งงบต่องานและต่อวันในหน้าตั้งค่า (0 = ไม่จำกัด) เลือกได้ว่าจะนับมูลค่าเทียบ API ของงานที่ใช้ subscription ด้วยหรือไม่

ระหว่างที่งานหนึ่งรออนุมัติ งานอื่นในคิวจะรอด้วย เพราะ Relay ทำทีละงาน

## ทำงานเป็นทีม (งานย่อย)

คนวางแผนประเมินความยากของงานเป็น `simple`, `medium` หรือ `hard` งานง่ายทำรวดเดียวด้วย AI หนึ่งตัวต่อฝั่งที่มีงาน งานกลางแบ่งเป็น 2–3 ชิ้นต่อฝั่ง งานยากแบ่งได้ถึงเพดานที่ตั้งไว้ แต่ละชิ้นมีเป้าหมาย ไฟล์ และเกณฑ์ตรวจของตัวเอง

ไปที่ **ตั้งค่า → ทำงานเป็นทีม** เพื่อกำหนดวิธีแบ่งงานและตรวจงานย่อย

- `team.mode` เลือก `auto` เพื่อแบ่งงานตามแผน หรือ `off` เพื่อให้ AI ทำรวดเดียวต่อฝั่งสำหรับงานที่ไม่มีรายการงานย่อยจาก Task Card ส่วน `team.maxSubtasks` จำกัดจำนวนงานย่อยไว้ที่ 2–6 ชิ้นต่อฝั่ง ค่าเริ่มต้นคือ 4
- `team.parallel` กำหนดจำนวนงานย่อยที่รันพร้อมกันได้ต่อฝั่ง เลือกได้ 1–3 ค่าเริ่มต้นคือ 2 ตั้งเป็น 1 เพื่อทำทีละชิ้นบน worktree ของฝั่ง โดยทำชิ้นที่เป็นเงื่อนไขก่อนและใช้ลำดับแผนเมื่อเลือกได้หลายชิ้น เมื่อเลือก 2 หรือ 3 Relay ประเมินจำนวน AI ที่พร้อมใช้ใหม่ก่อนปล่อยงานเพิ่ม งานย่อยแต่ละชิ้นใช้ worktree ชั่วคราวของตัวเอง แล้ว Relay รวมผลเข้า branch ของฝั่งตามลำดับแผน โดยให้ชิ้นที่งานอื่นต้องรอถูกรวมก่อน หาก merge ชนกัน Relay ยกเลิก merge รอให้งานที่กำลังรันในฝั่งนั้นจบ แล้วรันชิ้นที่ชนใหม่บน worktree ของฝั่งจากโค้ดที่รวมแล้ว
- `team.check` กำหนดว่าเมื่อไรที่หัวหน้าตรวจ diff ของงานย่อยที่แก้ไฟล์
  - `always` ตรวจทุกชิ้นที่มีการแก้ไข เป็นค่าเริ่มต้น
  - `hard` ตรวจเมื่อแผนประเมินงานเป็น `hard`
  - `off` ข้ามการตรวจงานย่อยและให้รีวิวรวมตอนท้ายตัดสิน

ทุกค่า `team.parallel` ให้เริ่มงานย่อยที่ระบุ `dependsOn` เมื่อชิ้นที่รอทำเสร็จ ผ่านการตรวจเมื่อเปิดใช้ และโค้ดอยู่ใน branch ของฝั่งแล้ว หากชิ้นที่รอถูกตัดออกเพราะเกินเพดานงานย่อย Relay จะแจ้งให้แก้แผนก่อนลงมือทำ การ์ด **ทีมงาน** แสดงสถานะ **รอ #n** พร้อมผู้รับงาน ผู้ตรวจ จำนวนรอบแก้ และผลตรวจ เมื่อหัวหน้าเจอปัญหา Relay ส่งชิ้นนั้นกลับให้แก้ได้หนึ่งรอบ

Relay รวมผลของแต่ละฝั่งเข้า branch ของงาน แล้วทดสอบตามที่ตั้งไว้และรีวิวรวม ฝั่งที่แผนระบุว่าไม่มีงานจะถูกข้ามพร้อมหมายเหตุ “แผนไม่มีงานส่วนนี้” โดยไม่เรียก AI ในขั้นลงมือทำ หากรีวิวพบปัญหาที่ฝั่งนั้นรับผิดชอบ Relay จะให้ฝั่งนั้นแก้บนโค้ดที่รวมแล้วและรีวิวอีกครั้ง

## งานที่ "ต้องตรวจเพิ่ม"

งานจะขึ้นสถานะนี้เมื่อแก้ตามรีวิวครบ `maxRounds` รอบแล้ว แต่รีวิวยังเจอปัญหาหรือเทสยังไม่ผ่าน ในหน้างานมีทางเลือกดังนี้

- **แก้ต่ออีกรอบ:** สั่งให้ AI แก้ปัญหาที่ค้างบน branch เดิม เพิ่มคำแนะนำได้ และเลือกได้ว่าจะให้ AI ตัวไหนแก้ จากนั้น Relay ทดสอบและรีวิวใหม่ 1 รอบ (API: `POST /api/jobs/:id/fix` ส่ง `{ note, provider }`) งานที่ไม่มีปัญหาค้างก็สั่งได้ถ้าใส่คำแนะนำ แต่งานที่ merge แล้วสั่งไม่ได้
- **คัดลอก prompt ให้ Claude Code:** ได้ข้อความพร้อมวางใน session ใหม่ มีโฟลเดอร์ worktree, branch, ปัญหาที่รีวิวเจอ, เทสที่ไม่ผ่าน และโจทย์เดิม ปุ่มนี้มีให้ทั้งงานที่ merge แล้วด้วย
- **Merge ทั้งที่ยังมีปัญหา:** ถ้ารับปัญหาที่เหลือได้

## การจ่ายงานแบบอัตโนมัติ

หน้า **ตั้งค่า → การจ่ายงาน** เลือกได้ 2 โหมด: **อัตโนมัติ** (ค่าเริ่มต้น) และ **กำหนดเอง** (ตารางตัวหลัก/ตัวสำรองเดิม)

ในโหมดอัตโนมัติ Relay ให้คะแนน AI ทุกตัวที่พร้อมใช้ในแต่ละขั้น แล้วเลือกคะแนนสูงสุด ตัวที่เหลือเรียงเป็นตัวสำรอง การเลือกไม่เรียก AI ช่วยตัดสิน จึงไม่เสียโควตา และอธิบายเหตุผลได้ทุกครั้ง

| ปัจจัย | ที่มา |
| --- | --- |
| ความเหมาะกับขั้น | ค่าตั้งต้นต่อ AI ต่อบทบาท (ใน `server/router.js`) Gemini ผ่าน API เห็นแค่ไฟล์ที่ Relay ส่งไป จึงเหมาะกับขั้นแก้โค้ดน้อยกว่า |
| โควตา | โควตาคงเหลือต่ำสุดของ AI นั้น หลังหักระดับที่กันไว้ ไม่มีข้อมูลโควตาให้ค่ากลาง |
| อัตราสำเร็จ | จากขั้นที่เคยทำใน 60 วันล่าสุด ใช้เมื่อ AI นั้นมีข้อมูลในขั้นนั้นอย่างน้อยตามจำนวนที่ตั้งไว้ (ค่าเริ่มต้น 5 ครั้ง) |
| ความเร็ว | เวลาเฉลี่ยของขั้นที่สำเร็จ ถ้ายังมีข้อมูลไม่พอใช้ค่าตั้งต้น |
| ต้นทุน | Gemini ที่เรียกผ่าน API มีต้นทุนจริง ตัวอื่นใช้ subscription |
| รีวิวต้องเป็นตัวอื่น | ขั้นรีวิวถูกตัดคะแนนถ้า AI นั้นเขียนโค้ดงานเดียวกัน |
| กระจายงานที่ทำพร้อมกัน | Backend กับ Frontend ถูกกระจายไป AI คนละตัวเมื่อคะแนนใกล้กัน |

- **โปรไฟล์:** สมดุล, เร็วที่สุด, ประหยัดที่สุด ปรับน้ำหนักของปัจจัยข้างบน Task Card เลือกโปรไฟล์เฉพาะงานได้ด้วย `routing.profile`
- **ดูเหตุผล:** ในประวัติงานมีบรรทัด "เลือกอัตโนมัติ: …" และแท็บ **การจ่ายงาน** ในหน้างานแสดงคะแนนของทุก AI ทุกขั้น หน้าตั้งค่ามีตาราง "ถ้าสั่งงานตอนนี้ Relay จะเลือก" จากข้อมูลจริงขณะนั้น
- **กำหนด AI เอง:** `routing.prefer` ใน Task Card ล็อก AI ของบางขั้น (ขั้นอื่นยังเลือกอัตโนมัติ) การเลือก AI ในหน้าสร้างงานปิดการเลือกอัตโนมัติของงานนั้น ถ้า AI ที่ล็อกไว้ไม่พร้อมใช้ Relay จะเลือกตัวอื่นแทน
- **ยังใช้กฎเดิมเสมอ:** ข้าม AI ที่ยังไม่เชื่อมต่อ ติด cooldown หรือโควตาต่ำกว่าที่กันไว้ รอโควตาและลองซ้ำตามโหมดอัตโนมัติ (เรื่องความต่อเนื่อง)

## ความจำของโปรเจกต์

- **บันทึกของโปรเจกต์:** เขียนในหน้า **โปรเจกต์** เช่นวิธีรัน ข้อตกลงในโค้ด หรือสิ่งที่ห้ามทำ AI ทุกตัวได้รับบันทึกนี้ทุกขั้น
- **งานล่าสุด:** เมื่องานเสร็จ Relay จำชื่องาน ผลรีวิว และไฟล์ที่แก้ไว้ 10 งานล่าสุด และส่ง 5 งานล่าสุดให้ AI ในงานถัดไป
- ถ้า repo มี `AGENTS.md` หรือ `CLAUDE.md` Relay ส่งไฟล์นั้นให้ AI ก่อนไฟล์อื่น และ Claude Code กับ Codex อ่านเองอยู่แล้ว

## เชื่อม Chat ผ่าน MCP

`mcp/server.js` เป็น MCP server แบบ stdio ที่คุยกับ Relay บนเครื่อง Relay ต้องเปิดอยู่ก่อน เครื่องมือที่มี:

| เครื่องมือ | ทำอะไร |
| --- | --- |
| `relay_list_projects` | รายชื่อโปรเจกต์และคำสั่งทดสอบ |
| `relay_create_task` | ส่ง Task Card ที่คุณสั่งเข้าคิวและเริ่มให้ AI ทำงาน |
| `relay_job_status` | สถานะงานเดียว หรือ 10 งานล่าสุด |
| `relay_job_result` | ผลรีวิว ผลทดสอบ token branch คำสั่ง merge และ diff |
| `relay_approve` | ตอบงานที่รออนุมัติ: อนุมัติ ขอแก้แผน หรือไม่อนุมัติ Claude ถูกสั่งให้เรียกเมื่อคุณตัดสินใจแล้วเท่านั้น |
| `relay_cancel_job` | หยุดงาน |
| `relay_quota` | โควตาของ AI แต่ละตัว |

เพิ่มให้ Codex (ใช้ได้ทุกโฟลเดอร์):

```powershell
codex mcp add relay -- node D:\AI\relay\mcp\server.js
```

เมื่อ Codex โหลดการเชื่อมต่อแล้ว สั่งได้ เช่น “สร้าง Task Card ในโปรเจกต์ AI Relay ให้แก้ปุ่มบันทึก โดยต้องแสดงผลสำเร็จและข้อความผิดพลาดให้ชัดเจน” เครื่องมือจะค้นหาโปรเจกต์ สร้างการ์ดที่มีเป้าหมาย ขอบเขต และเกณฑ์รับงาน แล้วส่งเข้าคิว การส่งการ์ดเริ่มใช้ AI และโควตาตามการตั้งค่าของ Relay โปรเจกต์ AI Relay บนเครื่องนี้ใช้ Git root `D:\AI` และตัวแอปอยู่ในโฟลเดอร์ `relay/`

เพิ่มให้ Claude Code (ใช้ได้ทุกโฟลเดอร์):

```powershell
claude mcp add --scope user relay -- node D:\AI\relay\mcp\server.js
```

เพิ่มให้ Claude Desktop: เปิด **Settings → Developer → Edit Config** แล้วเพิ่มใน `claude_desktop_config.json` จากนั้นปิดและเปิด Claude Desktop ใหม่

```json
{
  "mcpServers": {
    "relay": { "command": "node", "args": ["D:\\AI\\relay\\mcp\\server.js"] }
  }
}
```

ถ้า Relay ไม่ได้ใช้พอร์ต 4782 ให้ตั้ง `RELAY_PORT` หรือ `RELAY_URL` ใน `env` ของ MCP server การเชื่อมต่อแบบ stdio นี้ใช้กับ Codex, Claude Desktop และ Claude Code บนเครื่องเดียวกับ Relay

Claude Code แก้ไฟล์ได้เฉพาะใน worktree ของงาน ไม่มี shell (ดูหัวข้อการแก้โค้ดด้านบน) โหมดนี้ใช้บัญชี claude.ai ของคุณ จึงเหมาะกับการใช้งานส่วนตัวบนเครื่องของคุณ Relay ไม่เรียก Claude API โดยตรงและไม่ส่ง `ANTHROPIC_API_KEY` ให้ Claude Code จึงไม่มีค่าใช้จ่ายตาม API เพิ่ม
